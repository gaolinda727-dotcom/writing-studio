# Writing Studio · 高中英语写作学习空间

**Write. Reflect. Improve.**  
每一次写作，每一次反思，都让表达更进一步。

Writing Studio 是面向中国高中生的 AI 英语写作学习平台。通过写作、诊断、修改和反思的完整闭环，帮助学生将零散的写作练习转化为持续、可见、可衡量的能力提升。

本仓库提供可复用的写作学习网页生成工作流，以及一份可直接使用的单文件本机版。**当前 AI 反馈、匿名互评作品和成长曲线为预设演示，尚未连接真实 AI 批改、同伴匹配或云端学习记录。**

## 先打开学习网页

- [在线体验 Writing Studio](https://gaolinda727-dotcom.github.io/writing-studio/)
- [下载仓库 ZIP](https://github.com/gaolinda727-dotcom/writing-studio/archive/refs/heads/main.zip)
- [查看成品 index.html](index.html)

下载后，使用 Chrome 或 Edge 打开仓库根目录的 **`index.html`** 即可练习，无需安装依赖、联网或填写 API Key。它包含全部样式、脚本、题目和写前支架，可以把这个 HTML 文件单独发给学生。微信内无法运行时，请先保存到设备，再选择浏览器打开。

`assets/template.html` 是生成器使用的模板，含有占位符，**不要把模板当成学生使用的成品**。分享学习网页时发送根目录的 `index.html`。

## 示例内容

当前包含 **27 道原创示例题**，每个应用文文体、续写子主题各一题；这些材料不是考试真题。

| 写作方向 | 文体或主题 | 题数 |
| --- | --- | ---: |
| 应用文习作 | 邮件、邀请信、建议信、感谢信、道歉信、求助信、推荐信、申请信、告知信、通知、演讲稿、倡议书、日记、海报 | 14 |
| 读后续写 · 人与自我 | 个人成长、突破胆怯、战胜挫折、自我接纳 | 4 |
| 读后续写 · 人与社会 | 亲情友情和解、师生温暖、陌生人善意相助、诚信感恩、文化体验 | 5 |
| 读后续写 · 人与自然 | 野外遇险脱困、救助动物、守护自然、敬畏生命 | 4 |

应用文可按文体切换；续写先选主题语境，再选具体方向。每题提供任务要求、审题核对、写前支架、独立写作区和后续评价反思入口。

## 一篇作文的七步学习路线

1. **审题练习**：明确对象、目的、要点、语气，或梳理原文人物、冲突与线索。
2. **写前支架**：分析框架或续写思路，练习句型，完成分析小题并记录自己的构思。
3. **独立写作**：收起支架，只显示题目、空白正文、词数与保存状态；关闭拼写提示，构思不会自动填入正文。
4. **诊断与修改演示**：查看预设示例的反馈原句、修改建议与理由，理解修改方法。
5. **修改后自评**：依据教学参考量表评分，记录自己修改了什么及其理由。
6. **匿名互评演示**：阅读明确标为示例的作品，尝试评分、指出优点和提出建议；评价不会发送给真实学生。
7. **成长反思**：记录本次收获与下次目标，查看明确标为示例的成长报告样式。

应用文采用 15 分、续写采用 25 分的**教学参考量表**，并非官方评分标准；当前示例分数不能作为学生真实能力的测量结果。

## Skill 与成品的关系

**`SKILL.md` 描述给 AI 作者使用的生成工作流；`index.html` 是给学生使用的成品。** 教师可以让支持读取本地文件的 Agent 先阅读 Skill，再指定年级、文体、主题、题量或教学材料，修改题库和支架后重新生成网页。

```text
writing-studio/
├── README.md                  项目介绍与使用说明
├── SKILL.md                   给 AI 作者的网页生成工作流
├── index.html                 学生可直接打开的单文件成品
├── .nojekyll                  GitHub Pages 静态发布标记
├── package.json               可选的构建与检查命令入口
├── data/
│   ├── course.json            原创写作任务、示例与评价维度
│   └── scaffolds.json         按题目 ID 对应的写前支架
├── assets/
│   ├── template.html          含占位符的 HTML 模板
│   ├── styles.css             界面样式
│   ├── app.js                 学习流程与交互
│   └── local-auth.js          已打包的本机账号与备份模块
├── references/
│   ├── authoring.md           教学命题与内容校对约定
│   └── data-schema.md         数据字段和对应关系
└── scripts/
    ├── build.mjs              数据校验与单文件生成
    ├── validate.mjs           题库和支架结构校验
    ├── check.mjs              输出及应用检查
    └── lib.mjs                构建与检查共用函数
```

## 使用 Skill

在支持本地 Skill 的 Agent 环境中，可按该平台的说明安装本仓库，并保留子目录。也可以直接让 Agent 阅读仓库中的 `SKILL.md`，再提出生成要求；仅下载仓库不会自动安装 Skill。

示例请求：

> 请先阅读 Writing Studio 的 SKILL.md，为高一学生制作英语邀请信专项练习。设置 3 道不同情境的原创任务，提供审题核对、礼貌邀请句型和写前分析题；进入独立写作后收起所有支架，保留本机账号和记录备份。输出可直接打开的单个 HTML。

> 请为高二学生增加“人与自然—救助动物”读后续写任务。给出原创阅读材料和两段首句，写前引导学生分析线索、衔接和情绪变化。不要把原创材料标为真题，也不要把预设示例反馈说成真实 AI 批改。

## 修改与重新生成

需要 **Node.js 18 或更高版本**，不需要安装第三方依赖。在仓库根目录执行：

```bash
node scripts/validate.mjs
node scripts/build.mjs
node scripts/check.mjs
```

也可以指定课程数据和输出文件：

```bash
node scripts/build.mjs data/course.json index.html
```

如果使用 npm，可运行 `npm run build` 和 `npm test`。**直接使用现有 `index.html` 不需要 Node.js。**

修改任务时，编辑 `data/course.json`，并在 `data/scaffolds.json` 中更新同 ID 的支架；不要只改生成后的 HTML。字段约定见 [数据说明](references/data-schema.md)，命题要求见 [作者指南](references/authoring.md)。

同一任务的措辞优化可保留 ID；更换为不同任务时分配新 ID，避免旧草稿被显示为新题的作答。更新或替换文件前，先导出需要保留的学习记录。

## 本机账号、保存与备份

- 首次输入名字后设置本机密码，以后使用同一名字和密码登录；每次打开文件先进入登录页。
- 密码以随机盐和 PBKDF2-SHA256 摘要保存在当前浏览器中，不保存明文密码。账号用于本机学习档案区分，不等同于服务器账号体系。
- 草稿、写前构思、评分与反思按账号和题目分别保存在 `localStorage`，不会随 HTML 文件发给其他人，也不会自动上传 GitHub。
- 点击“记录备份”可以导出当前同学的 JSON 学习记录，备份不包含密码或密码摘要。换设备后，先创建或登录同名本机账号，再选择备份并确认合并导入。
- 文件路径、浏览器或网站域名变化，清理浏览器数据及隐私模式都可能影响本机记录。建议固定文件名和位置打开，并定期导出备份。
- 本机版与服务端线上版的账号、密码和记录分别管理，不会自动互通。浏览器存储不可用或空间不足时，页面会提示保存失败；请保留页面并先导出可导出的记录。

## 当前功能边界

本仓库可以独立运行写作练习与本机记录功能。它**没有连接真实 AI 服务、云端数据库、教师后台或真实同伴匹配服务**。诊断、互评作品与成长曲线均为明确标识的演示；不会分析学生输入的作文，也不会把演示评价发给其他人。

若要让不同设备共享同一账号、汇总班级记录或开展真实匿名互评，需要单独建设服务端并完成数据访问控制。不要把 API Key、学生备份、密码数据或服务端凭据提交到公开仓库。

## 发布到 GitHub Pages

把本仓库文件放在仓库根目录，确认成品名称是 **`index.html`**，不是 `index.html.html`。在 **Settings → Pages** 选择 **Deploy from a branch → main → /(root)** 并保存。部署完成后，可分享本项目的在线体验地址。

GitHub 仓库链接适合介绍项目与下载文件；GitHub Pages 链接适合学生直接打开学习。

## 检查与参考

构建和检查脚本用于发现数据字段、题目 ID、支架对应、内联输出及脚本语法等问题；自动检查不能替代目标浏览器的交互与布局试用。发布前，请用电脑与手机分别完成注册、重新登录、切换题目、写前练习、独立写作、保存以及备份恢复流程。

仓库信息组织参考用户提供的 [60days-zhongkao-vocab](https://github.com/zhishushu/60days-zhongkao-vocab) 与 [english-grammar-lab](https://github.com/Irisninijiang/english-grammar-lab) 示例。Writing Studio 的题目、支架和交互根据本项目需求制作，未复制参考项目的题库；文中没有把参考页面的验证结论当作本项目的浏览器验证结论。

本机密码模块包含 `@noble/hashes` 的预打包实现，其第三方许可说明保留在相应资源和生成的 HTML 中。
